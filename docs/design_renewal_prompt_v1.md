## 프로젝트: 톡비서(TokBiseo) 디자인 시스템 리뉴얼

### 1. 제품이 하는 일

카카오톡 오픈채팅방의 대화 내보내기(.txt)를 올리면, 멀티에이전트 AI가 **날짜별 기술 학습 리포트**를 만들어주는 모바일/데스크톱 앱입니다.

사용자는 개발 관련 오픈채팅방에 참여하고 있지만 하루에 수백 개씩 쌓이는 대화를 다 읽지 못합니다. 톡비서는 그 대화에서 잡담을 걷어내고, 언급된 기술을 웹/유튜브에서 조사해 검증한 뒤, "이 방에서 오늘 무슨 기술 이야기가 나왔고, 내가 뭘 공부하면 되는지"를 리포트로 정리해줍니다.

- 사용자: 20~30대 한국 개발자 / 개발 입문자
- 사용 맥락: 하루 1~2회, 주로 모바일에서 짧게 훑어보고, 관심 있는 주제만 깊게 파고듦
- 핵심 감정 목표: "정보 압박감"이 아니라 "오늘 뭘 배우면 되는지 알겠다"는 안도감

### 2. 반드시 지켜야 하는 기술 제약

- **Flutter + Material 3** (`useMaterial3: true`). 구현 가능한 범위 안에서 디자인해 주세요.
- 색상은 `ColorScheme.fromSeed(seedColor:)`로 생성한 팔레트를 기반으로 합니다. 따라서 **시드 컬러 1개 + 소수의 오버라이드(tertiary 계열 등)** 형태로 색상 체계를 제안해 주세요. 임의의 색 20개를 나열하는 방식은 코드로 옮기기 어렵습니다.
- **라이트 / 다크 모드 양쪽** 필수.
- 한글 전용 앱. 기본 폰트는 `BMJUA`(배달의민족 주아체) — 둥글고 굵은 손글씨풍 디스플레이 폰트입니다.
  - 지금 이 폰트를 본문까지 전부 적용하고 있어서 **긴 리포트 본문의 가독성이 떨어집니다.** 디스플레이/제목용과 본문용 폰트를 분리하는 타이포 체계를 제안해 주세요 (본문용 한글 폰트 추천 포함).
- 아이콘은 Material Symbols 범위 내에서.
- 모바일(주력) + Windows 데스크톱(부가) 양쪽에서 동작합니다. 반응형 레이아웃 규칙이 필요합니다.

### 3. 현재 화면 인벤토리

하단 `BottomNavigationBar` 3탭 + `IndexedStack` 구조입니다.

| 화면 | 역할 | 현재 구성 |
|---|---|---|
| **홈** (탭 1) | 단톡방 목록 | 방 카드 리스트(아이콘 48px + 방 이름 + "N일 요약 완료 · N개 메시지" + ⋮ 메뉴), FAB "단톡방 추가", 빈 상태(아이콘 80px + 안내문 + 버튼), 에러 배너, 진행률 바 |
| **방 상세** | 파일 업로드 + 해당 방의 날짜별 요약 목록 | .txt 업로드 버튼, 요약할 날짜 선택 UI, 날짜별 요약 리스트 |
| **달력** (탭 2) | 요약이 있는 날짜를 달력에 표시 | 월간 달력 + 요약 존재 날짜 마커, 날짜 탭 → 요약 상세 |
| **요약 상세** | 리포트 본문 — **앱의 핵심 화면** | 아래 4섹션 (상세 설명) |
| **설정** (탭 3) | API 키, 서버 URL 등 | 긴 폼 리스트 (약 640줄 분량, 현재 가장 정리가 안 된 화면) |

### 4. 요약 상세 화면 — 리포트 구조 (가장 중요)

AI가 생성한 마크다운을 4개 섹션으로 파싱해서 각각 다른 위젯으로 렌더링합니다. 이 화면의 정보 위계를 다시 잡는 것이 리뉴얼의 최우선 목표입니다.

1. **헤더** — 채팅방 이름 + "N개 메시지" (현재: Card)
2. **주제 키워드** — 키워드 5개 내외 (현재: `Chip` 가로 `Wrap`, tertiary 크림옐로 배경)
3. **대화 주요 내용** — 마크다운 본문. 문단 + 불릿 (현재: Card 안 `MarkdownBody`)
4. **핵심 정보** — 주제별 소섹션 N개. 각 소섹션에 조사된 웹/유튜브 링크와 설명이 들어감 (현재: Card 안에 `ExpansionTile` N개, 기본 접힘)
5. **톡비서 제안** — 주제별 학습 로드맵 N개. 링크·영상 포함, 가장 실용적인 섹션 (현재: 주제별 개별 Card, elevation 2)

마크다운 안에 등장하는 요소: 문단, 불릿/번호 리스트, **볼드**, 인라인 `코드`, 하이퍼링크, `>` 인용문(학습 목표/팁).

### 5. 현재 디자인의 문제점 (이걸 해결해 주세요)

1. **Card 남용** — 거의 모든 것이 흰 Card입니다. Card 안에 Card, Card 안에 ExpansionTile이 중첩되어 있어 어디가 그룹의 경계인지 읽히지 않습니다.
2. **정보 위계가 평탄함** — 5개 섹션이 시각적으로 거의 동등한 무게를 가집니다. "제안"이 가장 중요한데 눈에 먼저 들어오지 않습니다.
3. **스캔이 불가능함** — 리포트가 길어서 스크롤을 많이 해야 하는데, 훑어보며 관심 주제를 찾을 장치(요약 배지, 스티키 헤더, 섹션 내비게이션, 접힘 상태 미리보기)가 없습니다.
4. **브랜드 부재** — 딥블루 시드 + Material 3 기본값이라 순정 Flutter 데모처럼 보입니다. "톡비서"라는 비서 캐릭터 컨셉이 시각적으로 전혀 드러나지 않습니다.
5. **본문 가독성** — 디스플레이 폰트(BMJUA)로 긴 기술 문서를 읽게 만들고 있습니다.
6. **진행 상태 표현이 빈약함** — AI 파이프라인이 7단계(잡담 필터링 → 대화 분석 → 조사 계획 → 웹 검색 ∥ 유튜브 검색 → 자료 검증 → 리포트 작성)를 거치며 수십 초~수 분 걸립니다. 지금은 단순 진행률 바뿐이라 기다리는 시간이 지루하고 불안합니다. **이 대기 경험 자체를 설계해 주세요.**

### 6. 참고: 현재 색상 (교체 대상)

- 시드: `#1565C0` 딥 블루
- 액센트(tertiary): 라이트 `#996515` 골드 / 다크 `#FFD54F`, 칩 배경 라이트 `#FFF3CD`
- 카카오톡 옐로우를 액센트로 쓰려는 의도였으나 지금은 탁한 골드/브라운으로 보입니다. 카카오와의 연상은 유지하되 **더 세련되고 독자적인 방향**을 원합니다. 카카오 브랜드를 그대로 베끼지는 말아 주세요.

### 7. 원하는 산출물

1. **디자인 토큰** — 시드 컬러 + ColorScheme 오버라이드(라이트/다크), 타이포 스케일(디스플레이/제목/본문/캡션 + 폰트 지정), 스페이싱 스케일, 라운딩, elevation/보더 사용 규칙
2. **컴포넌트 스펙** — 방 카드, 키워드 칩, 리포트 섹션 컨테이너, 접힘형 주제 카드, 제안 카드, 진행 상태 인디케이터(7단계), 에러 배너, 빈 상태, FAB, 다이얼로그, 설정 항목
3. **핵심 화면 3개 시안** — 홈(방 목록) / 요약 상세 / AI 처리 중 대기 화면. 라이트·다크 양쪽.
4. **"컨테이너를 언제 쓰는가" 규칙** — Card / 보더 / 배경색 구분 / 여백만으로 구분 중 무엇을 언제 쓸지 명시. 지금 Card 남용의 근본 원인이 이 규칙의 부재입니다.
5. **정보 위계 설계** — 요약 상세 화면에서 5개 섹션의 시각적 무게 서열과 그 근거.

### 8. 하지 말아야 할 것

- 색을 화려하게 늘리지 마세요. 절제된 팔레트 + 명확한 위계가 목표입니다.
- 그라디언트, 글래스모피즘, 과한 그림자 같은 트렌드 효과는 피해 주세요. Flutter에서 성능 비용이 크고 유지보수가 어렵습니다.
- 커스텀 일러스트레이션 에셋이 대량으로 필요한 방향은 피해 주세요 (제작 리소스 없음).
- Material 3에서 벗어나 완전한 커스텀 위젯을 새로 만들어야 하는 방향은 피해 주세요.

## 부록: 후속 작업으로 디자인이 반영될 화면

디자인 리뉴얼 이후 다음 기능이 추가될 예정입니다. 컴포넌트 설계 시 고려하면 좋습니다.

- **노션 연동 상태 표시** — 리포트가 노션에 저장됨/실패함, 노션 페이지 열기
- **발행 워크플로우** — 리포트를 티스토리 블로그로 발행. 발행 상태(초안 / 발행 대기 / 발행 완료 / 실패) 배지와 발행 화면이 필요해집니다.
